## Не закрито (з причиною)

**Авторизації в API немає.** `services/api/src/routes/chat.ts` бере `household_id` і `user_id` напряму з тіла HTTP-запиту, без сесії чи токена. Технічно будь-хто, хто знає (чи вгадає) `household_id`, може писати в чужу комору або читати чужі картки. Не закрив, бо це дизайн-рішення для окремого кроку (auth/сесії), не патч на льоту — і зараз користувачів двоє, тому не терміново, але це не можна забути перед тим, як з'явиться третій.

**Облік токенів не пишеться нікуди.** `usage.input`/`usage.output` рахується на кожен виклик моделі (`services/api/src/model.ts`) і повертається в HTTP-відповіді, але жодна таблиця це не зберігає. `04-roadmap.html` сам називає це незворотним боргом («потім не відновити заднім числом») — і воно вже не відновлюється за час цієї сесії. Не закрив, бо потребує рішення про схему (нова таблиця? колонка в `message`?), а не однореченнєвого фіксу.

**Каталог — 131 з 1500–2500 за roadmap.** Реальні дані одного домогосподарства, не довідник української кухні. Хтось скаже «гречка» чи «кабачок» — резолвер поки цього не знає.

**Запрошення в дім посиланням — відсутнє повністю.** Ні роуту, ні таблиці. `household`/`household_member` є, механізму додати туди когось, крім прямого INSERT, немає.

## Технічний контекст (нерелевантно для Claude Code, для довідки)

Ця сесія працювала через Cowork-міст до Мака (ізольована Linux VM, не той самий термінал). SSH до GitHub з цього мосту заблокований мережею — довелось ставити `gh` CLI вручну й проганяти OAuth device flow через браузер для кожного push. `pnpm test` локально в цьому середовищі падає (rollup зібраний під Linux aarch64, а `node_modules` — під macOS arm64 з Мака) — тому зміни каталогу перевірені через реальний CI, не локально. У Claude Code, що працює прямо в терміналі, жодної з цих обхідних дій не буде потрібно.
