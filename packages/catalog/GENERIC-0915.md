# Загальні записи каталогу для родових слів · 15.09 (GENERIC-0915)

Власник 15.09: 12 із 20 найчастіших слів («кефір», «сметана», «хліб»…) не отримували ключа —
у довіднику були лише варіанти («Кефір 1%», «Гречка ядриця»). Код резолвера не чіпався: кожне
родове слово стало точним аліасом свого загального запису (`gen_*`, блок `CATALOG_GENERIC` у
`seed.ts`, джерело — `generic-0915.ts`). Уточнення («кефір 1%», «гречка зелена») і далі беруть
точний запис — exact бʼє anchored; `priority: -1` — за рівного збігу конкретний варіант сильніший.
Категорії, зона й алергени — з типового варіанта; нутрієнти — його ж, позначені `estimate` і
округлені (правило integrity).

Джерела кандидатів: seed стенда, eval- і чекові фікстури, тестові комори (186 слів у назвах партій)
+ кухонний словник ~150 слів. Із ~270 слів ключ мали 127; серед тих, що не мали, продуктових родових —
47 (решта — прикметники, бренди, службові слова).

## Строк для швидкопсувних — консервативний (власник 15.09)

Для gen_cheese, gen_fish, gen_sausage, gen_salami, gen_cream, gen_curd, gen_liver, gen_shrimp,
gen_herring, gen_turkey, gen_pork, gen_beef, gen_veal, gen_chicken_* строк (sealed) — найкоротший серед
видових варіантів групи (ключі за префіксом; фарш, субпродукти, напівфабрикати й домашня ковбаса —
не в групі, це інший рід). Правило строку живе в категоріях, тому категорії такого запису беруться з
варіанта, що дає мінімум: «Сир» → 21 дн (мʼякий, як моцарела), а не 60 (твердий); «Ковбаса» → 4 дн
(варена/сосиски), а не 30. Решта груп збіглась із типовим. Помилка «спливає раніше» дешевша за
«тихо зіпсувалось». Строк ПІСЛЯ відкриття в каталозі не живе — його дає модель тегом
`shelf_open_days` на продукті, тож тут лише sealed. Тест: `gen_* ≤ min(групи)`.

## Наслідки, які треба звірити (власник)

1. **Родова голова в чекових рядках тепер бере загальний запис**, а не мовчить: «Хліб Салтівський особливий» → «Хліб» (dry), «Сир Гауда 45%» / «Сир Моцарела» / «KASEREI СИР КАМБОЦОЛА 70%» → «Сир» (твердий), «Масло Ферма 73%» → «Масло», «Олія Олейна 1л» → «Олія». Категорія й зона правильні, але видовий запис (гауда, моцарела, камбоцола) не береться — рядок «Сир <вид>» завжди дає «Сир твердий». Це той самий anchored-рівень, що в чаті; окремий «суворий» для чеків у коді нема (`resolveReceiptKey` теж anchored). Якщо для чеків це небажано — потрібне правило про родові голови в резолвері (код), окремим рішенням. Фікстура receipt-corpus (KASEREI) переведена на `gen_cheese` з приміткою.
2. **«сир», «риба», «свинина», «яловичина» перестали бути категоріями** для позначки «?рід» у контексті моделі (`categoryBreadth` → null, як «курка»): тепер це товари. Тест domain `generic-label` переведено на «молочне»/«птиця».
3. Спірні вибори типового варіанта позначені в таблиці: масло = вершкове; сир = твердий, творог = кисломолочний 9%; риба = хек (морозилка); помідори = свіжі (сливка), не пелаті; оселедець = маринований; перець = солодкий овоч; салат = айсберг; паста = макарони; сік = апельсиновий; вино = червоне сухе; паприка = спеція; яловичина = свіже мʼясо (соломкою), не тушкована.

## Бекфіл наявних продуктів

Ключ рішається раз при народженні продукту, тож наявні продукти без ключа новим довідником самі не
підхопляться. Разовий бекфіл (лише в дірку, тим самим шляхом, що `ensureProduct`; наявні ключі не
чіпаються; ідемпотентний): ядро — `@kitchen/domain` `backfillGenericKeys`; для стенда —
`packages/db/scripts/backfill-generic-keys.ts` (dry-run без `--apply`); для проду — адмін-ендпоінт
`POST /v1/admin/backfill-generic-keys` (dry-run) / `?apply=1` (запис) за адмін-гейтом, повертає
той самий лог: «було N без ключа → M отримали (слово→ключ), K лишились». Запуск на проді — власник
після деплою.
