# Спека для агента-генератора каталогу Kitchen OS

Ти генеруєш позиції каталогу інгредієнтів для українського домашнього продукту.
Продукт живе в Україні: у каталозі має бути те, що реально купують в українських
мережах (Сільпо, АТБ, Метро, Novus, Varus) і те, що реально звучить у мовленні й у чеках.

## Куди писати результат

Робоча директорія на машині користувача. Усі команди — через `mcp__remote-devices__device_bash`.
Твій файл: `$HOME/mnt/KITCHEN_OS/packages/catalog/data/raw/<ТВІЙ_ФАЙЛ>.ndjson`

Формат — **NDJSON**: один JSON-обʼєкт на рядок, без коми в кінці, без масиву-обгортки.
Пиши порціями по 20-30 позицій, кожна порція — окремий виклик device_bash з heredoc:

```
mkdir -p "$HOME/mnt/KITCHEN_OS/packages/catalog/data/raw" && cat >> "$HOME/mnt/KITCHEN_OS/packages/catalog/data/raw/<ТВІЙ_ФАЙЛ>.ndjson" <<'EOF'
{"key":"chicken_breast","name":"Куряче філе", ...}
{"key":"chicken_thigh","name":"Куряче стегно", ...}
EOF
```

Перша порція — з `>` (перезапис), решта — з `>>` (дозапис). Не пиши більше ~30 обʼєктів
за один виклик: команда завелика і shell має короткий таймаут.

Наприкінці перевір себе:
```
wc -l "$HOME/mnt/KITCHEN_OS/packages/catalog/data/raw/<ТВІЙ_ФАЙЛ>.ndjson"
node -e "require('fs').readFileSync(process.argv[1],'utf8').split('\n').filter(Boolean).forEach((l,i)=>{try{JSON.parse(l)}catch(e){console.log('BAD LINE',i+1,e.message)}})" "$HOME/mnt/KITCHEN_OS/packages/catalog/data/raw/<ТВІЙ_ФАЙЛ>.ndjson"
```
Якщо є BAD LINE — виправ (перепиши файл заново).

## Схема одного обʼєкта

```jsonc
{
  "key": "chicken_breast",              // snake_case, латиниця, унікальний, англійською
  "name": "Куряче філе",                 // канонічна українська назва, з великої літери
  "aliases": ["куряче філе", "філе куряче", "курячого філе", "chicken breast", "філе курки"],
  "categories": ["куряче філе", "курка", "птиця", "мʼясо", "тваринне"],
  "allergen_groups": [],                 // ЗАВЖДИ порожній масив. Пояснення нижче.
  "zone_default": "fridge",              // dry | fridge | freezer | fresh | spices | drinks
  "unit_weight": 180,                     // ОПЦІЙНО, грами «однієї штуки» для поштучного
  "density": 0.92,                        // ОПЦІЙНО, g/ml — тільки для рідин
  "nutrition": {"kcal":110,"p":23,"f":2,"c":0}  // ОПЦІЙНО, на 100 г, цілі числа
}
```

### key
- snake_case латиницею, англійська основа: `pork_neck`, `sour_cream_20`, `basmati_rice`.
- Унікальний у межах усього каталогу. Щоб не збігтися з іншими агентами, тримайся
  свого префікса, якщо він виданий у завданні.
- Якщо продукт відрізняється лише жирністю/сортом — вписуй це в key: `milk_cow_25`, `cream_33`.

### name
Канонічна українська назва, як людина назве продукт уголос. Не назва з цінника
дослівно, не рекламний опис. «Сметана 20%», а не «Сметана Яготинська 20% 350г».

### aliases — найважливіше поле
Це те, як продукт зустрічається в чеках і в мовленні. 4-9 штук. Обовʼязково:
- **нормальна форма** («часник»)
- **відмінкові форми** для того, що часто кажуть уголос: «часнику», «часником»,
  «кінзу», «кінзи», «сметани», «моркву», «моркви». Морфології в коді немає — вона
  живе тільки тут. Для рідковживаних позицій відмінки не обовʼязкові.
- **інверсія слів**: «філе куряче» поряд із «куряче філе».
- **латиниця** для міжнародних назв: `mozzarella`, `basmati`, `prosciutto`, `tahini`.
- **русизм/суржик**, якщо він реально в чеках: «подсолнечное масло» — ні; «пельмені» — так.
- **бренд** — тільки якщо ти впевнений, що цей бренд реально є в українських мережах
  (Яготинське, Наша Ряба, Roshen, Торчин, Верес, Чумак, Моршинська, Хортиця).
  Не вигадуй брендів. Сумніваєшся — не пиши бренд.

### ЗАБОРОНЕНІ аліаси
1. Усе, що є у файлі `data/reserved.json` у полях `aliases` і `names` — це аліаси
   131 наявної позиції. Прочитай файл перед стартом. Твої аліаси не повинні
   **точно збігатися** з жодним із них.
2. Голі родові однослівні терміни, якщо твоя позиція — не канонічний носій терміна:
   «сир», «молоко», «вода», «мʼясо», «риба», «хліб», «сік», «олія», «борошно», «цукор»,
   «сіль», «чай», «кава», «пиво», «вино». Для «Сир Гауда» аліас «сир» — заборонений,
   «гауда» — так.
3. Аліас коротший за 3 символи.

### categories — ієрархія від конкретного до загального
Приклад: `Ковбаса Міланська` → `["ковбаса","сирокопчене","свинина","мʼясо","тваринне"]`.

Категорії — це те, **чим продукт є**, а не де він лежить у магазині. На категоріях
тримаються два механізми:
- антипатерн «не їм свинину» ловить усе, у чого є категорія `свинина`;
- алергія «молюски» ловить усе, у чого є категорія `молюски`.

Тому:
- Категорія тваринного походження мусить закінчуватись коренем: `тваринне` для всього
  зі звірів/риби/птиці; `рослинне` — для рослинного (нова категорія, використовуй її);
  `нехарчове` — для побутової хімії й паперу.
- Вписуй **справжню родову приналежність**, навіть якщо вона очевидна:
  сир → `молочне`; лосось → `риба`; креветка → `ракоподібні`, `морепродукти`;
  мигдаль → `горіхи`; пшеничне борошно → `пшениця`, `зернові`; тофу → `соя`.
  Це не «здогадка про алерген» — це чесна таксономія.
- Свинина/яловичина/курятина/індичка — окремими категоріями, бо на них тримаються
  релігійні та особисті обмеження.
- 3-5 рівнів. Не менше 2.
- Перевикористовуй наявні терміни з `data/reserved.json` → `categories`, а не вигадуй
  синоніми до них («мʼясо», а не «мʼясне»).

### allergen_groups — ЗАВЖДИ `[]`
Не заповнюй це поле. Взагалі. Рішення користувача: алергени вносяться окремим
ручним списком, за який відповідає одна людина, а не виводяться агентом.
Якщо напишеш щось у цьому полі — воно все одно буде затерте на етапі збірки.
Твоя робота з алергенами — чесні `categories` (див. вище). Цього достатньо.

### zone_default
- `fresh` — свіжі овочі, фрукти, зелень (те, що не обовʼязково в холодильнику)
- `fridge` — молочне, мʼясо охолоджене, готове
- `freezer` — заморозка
- `dry` — бакалія, консерви, снеки, побутова хімія
- `spices` — спеції й сушені трави
- `drinks` — напої, включно з алкоголем

### nutrition
Опційно, на 100 г продукту, цілі числа, груба оцінка (похибка 20-30% прийнятна —
це орієнтир, не медичні дані). Став тільки там, де впевнений у порядку величини.
Для побутової хімії, паперу, води — не став.

## Чого НЕ робити
- **Не копіювати описи продуктів з сайтів мереж** — це чужий текст. Назви й аліаси — ок.
- **Не вигадувати бренди й продукти.** Якщо не впевнений, що це реально продається
  в Україні — не додавай. Краще 90 справжніх, ніж 150 із вигаданими.
- **Не додавати екзотику без причини.** «Мамалига з чіа» не потрібна. Потрібне те,
  що реально купують. Kitchen OS цільово для української кухні; сюди входить і те,
  що українці реально готують — паста, суші-набір, кімчі — але не весь світовий асортимент.
- **Не дублювати** позиції всередині свого файлу: перед фінальною порцією перечитай,
  що вже написав.
- **Не чіпати** нічого, крім свого файлу в `data/raw/`. Ні `seed.ts`, ні `logic.ts`,
  ні `.env`, ні git.

## Перед стартом обовʼязково
```
cat "$HOME/mnt/KITCHEN_OS/packages/catalog/data/reserved.json"
```
— це 131 наявна позиція: їхні keys, aliases, names і словник категорій.
Не дублюй їх і не конфліктуй з ними.
