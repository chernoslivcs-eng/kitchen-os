# Раунд 4 — профіль як сім речень

Статус: дизайн затверджено (Профіль v6), копі затверджено як є. Цей документ — контракт для реалізації. Кроки 2–9 нижче йдуть по одному, кожен — окремий коміт у гілці `audit/round-4`, деплой тільки після ручного тесту власника.

## 1. Що міняється і що ні

Міняється все, що торкається профілю: модель даних, серіалізація в промт, картка профілю, вето, сторінка `/profile`, онбординг у стрічці, новий канал «нотатки».

Не міняється: комора, список, рецепти, календар, життєвий цикл карток (`applied_at / undone_at / dismissed_at`), repeat-guard, tense, recipe-dedup, example-guard, голос.

Родина, гості, «стіл на сьогодні», календарні набори свят — раунд 5. Схема нижче їм не заважає (поле `subject` закладено, не використовується).

## 2. Модель даних

### 2.1. `profile_text` — сім полів на користувача

| key | Початок речення | Ліміт | Індексується |
|---|---|---|---|
| `name` | Мене звати | 30 | ні |
| `no` | Я не їм | 200 | так → вето |
| `ban` | Мені не можна | 140 | так → вето + прапорець алергії |
| `love` | Я люблю | 200 | ні |
| `meh` | Я не дуже люблю | 200 | ні |
| `kit` | У мене на кухні є | 260 | ні (читає модель) |
| `when` | Я зазвичай готую | 250 | ні |

Кожне поле: `text` (string, обрізається по ліміту на сервері), `status`: `empty` (ще не відповідали) · `filled` · `none` («Нічого такого» — свідомо порожньо, не перепитувати), `updated_at`.

Ліміти — з дизайну, не міняти. Початки речень — константи в `packages/domain`, одне джерело для UI, промту й карток.

### 2.2. `notes` — рядки від асистента

`id, user_id, subject (null), text ≤ 140, source ('assistant' | 'user'), created_at, deleted_at (soft — для «Повернути»), norm_hash` (нормалізований текст для дедупу).

Людина видаляє; не редагує. У промт ідуть останні 10 не видалених.

### 2.3. `veto_index` — похідне, не редагується

Перебудовується при кожному збереженні `no` або `ban`.
`user_id, field ('no' | 'ban'), kind ('category' | 'product' | 'free'), ref (id категорії або продукту каталогу, null для free), label (як у тексті), subject (null)`.

Правила витягу (консервативні):
- беруться лише поля `no` і `ban`; «Я не дуже люблю» ніколи не потрапляє у вето;
- фрази → категорії каталогу через словник пресетів у домені: «нічого тваринного / веган» → мʼясо, птиця, риба, морепродукти, молочне, яйця; «пескетаріанець» → мʼясо, птиця; «вегетаріанець» → мʼясо, птиця, риба, морепродукти; «халяль» → свинина, алкоголь; «пісне» → тваринне; список закритий, розширюється кодом;
- окремі слова → продукт або категорія каталогу за назвою/аліасом (той самий матчинг, що в коморі);
- що не розвʼязалось — `kind: free`, у вето не бере участі, читає лише модель;
- прапорець алергії: усе з `ban` + рядки з `no`, де в тексті є «алергі» (стем).

### 2.4. Міграція 0023 (Postgres + InMemory)

Створює три таблиці; переносить існуючі записи `profile_entries`:
- `allergy` → `ban` (через кому);
- `anti` → `no`; `wish`, що збігається зі словником пресетів (веганство, пескетаріанство…) → `no`; решта `wish` → `love`;
- `equip` → `kit`;
- `note` → `notes` (source: user);
- `intent` → `notes` (source: user, текст «хотів: …»);
- `tradition`, `member` — не переносяться (раунд 5), лишаються в старій таблиці;
- дублікати після злиття (наприклад «не їм риби» при «не їм … риби») — не чистити автоматично; власник поправить руками.

Стара таблиця не видаляється до кроку 9.

### 2.5. Прапор

`PROFILE_V2` (env). Вимкнений: усе працює як зараз. Увімкнений: читання/запис профілю, серіалізація, вето, UI — нові. Вмикається на локальному стенді на кроці 5, на проді — на кроці 9.

## 3. Промт

`serializeProfile` під прапором віддає блок дослівно:

```
[ПРО ЛЮДИНУ — її власні слова]
Мене звати Пилип.
Я не їм мʼяса, птиці, риби, яєць і молочного. Кінзу не беру.
Мені не можна — нічого такого.
Я люблю тайську кухню, помідори, супи.
Я не дуже люблю готувати великими порціями. Гостре — без фанатизму.
У мене на кухні є гриль, блендер, занурювальний блендер, тостер, фритюрниця. (Плита, духовка, мікрохвильовка, холодильник — є за замовчуванням.)
Я зазвичай готую ввечері, на одного-двох, з того, що є. До години — норм, довше — тільки на вихідних.

[НОТАТКИ — записав сам після розмов і готувань]
04.09 — Феттучіне вийшли пересолені: пармезан сам солоний, воду солити менше.
02.09 — Духовка гріє градусів на 20 сильніше, ніж показує.
```

Правила:
- поле `empty` — рядок пропускається; `none` — «— нічого такого»; `filled` — початок + текст як є;
- у `kit` завжди додається дужка про базу — це єдине, чого людина не писала;
- блок стоїть там, де зараз стоїть серіалізація профілю (місце перевірене в раунді 3); не переносити;
- з `kitchen-policy.md` прибирається правило «Я веган → wish + anti» і все про типи профілю; замість нього одне речення: «Про людину — читай блок [ПРО ЛЮДИНУ] як її слова; „Я не їм" і „Мені не можна" — не пропонувати ніколи, „не можна" — без жартів і з попередженням, коли рецепт просять прямо»;
- `state-facts` — без змін, окрім назв блоків.

## 4. Картка профілю

Схема (замість `{kind, value}`):

```
{ type: 'profile', field: 'no' | 'ban' | …, mode: 'append' | 'replace', text: string, onboarding?: boolean }
```

- `append` — дописати до існуючого тексту через «. » (обрізка по ліміту; якщо не влазить — картка все одно застосовується, текст обрізається, у репліці асистент каже, що не влізло);
- `replace` — лише для онбордингу й для явного «поправ: …»;
- кнопка одна — «Записати» (`CARD_BUTTON_LABEL`), для `onboarding: true` друга дія — «Пропустити» → `dismissed_at`; для `field: 'ban'` замість «Пропустити» — «Нічого такого» → `status: none`, картка вважається застосованою;
- фраза в чаті, що заповнює поле (`«я веган»` → картка `no`), при наявній відкритій онбординг-картці того ж поля закриває її як застосовану — одна дорога в одне поле;
- у `[ОСТАННІ ДІЇ]` картка профілю показується як «записав у "Я не їм": …»;
- undo працює як для всіх карток (повертає попередній текст поля).

Онбординг: при першій сесії сервер видає сім карток по черзі (наступна — після застосування/пропуску попередньої, або всі одразу — вирішити в кроці 7 з дизайном); ілюстрація — `illustration: key`; стан «які видані» — у `profile_text` достатньо `status` полів, окремої таблиці не треба.

## 5. Вето

`allergen-veto.ts` → `veto.ts`:
- вхід: `veto_index` користувача + кандидат-рецепт;
- рецепт відхиляється, якщо будь-який інгредієнт належить до категорії з індексу (через ієрархію каталогу) або збігається з продуктом з індексу;
- для рядків із прапорцем алергії — поточна поведінка: зачистка згадки з репліки на непрямий запит, пряме попередження на прямий;
- `free`-рядки вето не читає;
- логувати відхилення (recipe id, рядок індексу) — щоб бачити, що спрацювало.

## 6. API

- `GET /v1/profile` → `{ fields: {key: {text, status}}, notes: [...], defaults: { kit: [...] } }`
- `PATCH /v1/profile/:key` `{ text }` або `{ status: 'none' }` — автозбереження; повертає перебудований `veto_index` для поля (для рядка «тримаю окремо», якщо колись знадобиться);
- `DELETE /v1/profile/notes/:id` → soft delete; `POST /v1/profile/notes/:id/restore` (вікно 5 с на клієнті, на сервері без обмеження);
- старі ендпоінти профілю під прапором повертають 410.

## 7. Нотатки від асистента (крок 8)

Єдина зміна контракту моделі: у відповіді необовʼязкове поле `note: string | null`.

Сервер: ≤ 140 знаків; дедуп по `norm_hash` проти останніх 30; не більше 3 на день; не записувати, якщо текст збігається з полем профілю або з нотаткою, яку людина видалила за останні 30 днів.

Правило в промті (у `kitchen-policy` або окремим блоком, вирішити по overlap-lint): нотатка — це те, що буде корисно памʼятати через тиждень і чого людина не казала прямо про себе: висновок про страву, про техніку, разове побажання з датою. Не нотатка: те, що вже є в [ПРО ЛЮДИНУ], сьогоднішні наміри, оцінки людини. Одна нотатка на хід, частіше — жодної.

## 8. UI

`/profile` — за Профіль v6: сторінка «Профіль»; секції «Про тебе» (сім рядків, підказка справа на десктопі / під рядком на мобільному, лічильник під час набору, текст ліміту), «Нотатки» (дата, текст, «прибрати», тост «Прибрано. Повернути»), «Мережі», «Акаунт». Автозбереження по blur і по паузі 800 мс; Enter — blur.

Стрічка — картка профілю в двох варіантах: звичайна (рядок + «Записати») і онбординг (ілюстрація, заголовок, підказка, рядок, «Записати / Пропустити | Нічого такого»); згорнутий стан — рядок «Я не їм мʼяса…  ЗАПИСАНО / ПРОПУЩЕНО».

## 9. Eval

Нові фікстури (спершу червоні):
- `diet-pescatarian-steak` — `no: «мʼяса й птиці»`, комора з яловичиною, «що на вечерю» → жодного мʼясного кандидата (перевіряти через вето-лог, не через текст);
- `diet-vegan-fish-sauce` — прихований інгредієнт у рецепті;
- `ban-without-word` — `ban: «арахіс»` без слова «алергія» → попередження на прямий запит, зачистка на непрямий;
- `meh-less-meat` — `meh: «багато мʼяса»`, три мʼясні в [ОСТАННІ ДІЇ] → пропозиція без мʼяса (текстова перевірка, мʼяка);
- `profile-verbatim` — інваріант: текст полів присутній у промті дослівно;
- `onboarding-phrase-closes-card` — «я веган» при відкритій картці `no` → картка застосована, поле заповнене.

Снапшоти раунду 3 перепрогнати після кроку 3 — голос не має змінитись.

Відхилення від контракту та рішення поза його буквою:

- **Адаптер під вимкненим прапором** (§4 не передбачав): промт один, і з `PROFILE_V2=0` сервер перекладає картку поля в ops-картку v1 — прапор лишається відкатом на проді.
- **`card.skipped`** у картці онбордингу: у `profile_text.status` немає значення «пропущено», а перезавантаження не мало скидати панелі; окремої таблиці, як і вимагав §4, немає.
- **`profile_note`**, а не `notes`: однина за конвенцією схеми; методи Repo з префіксом `Profile*`, бо `listNotes/deleteNote` зайняті `memory_note` до кроку 9.
- **Колонка `allergy` у `veto_index`** (не в списку §2.3): прапорець per-row, інакше вето мусило б наново різати текст поля.
- **Перегенерація** пропозиції й рецепта після дієтного збігу — один повторний виклик із «без …»; §5 говорив лише про відхилення кандидата.
- **Прямий запит** для «Я не їм»: рядок, названий людиною, на цей хід не вето; страву дають з одним реченням нагадування. Для «Мені не можна» — як і було.
- **Ops-картка profile** збережена для `tradition|member` (календар і домашні — раунд 5); `note|intent` перейшли в поле `note` на кроці 8.
- **`[ТРАДИЦІЇ]`** окремим блоком під прапором — §3 блок дослівний, а календар ще читає традиції зі старого профілю.
- **Промт спільний для обох прапорів** — гілка не може деплоїтись із вимкненим прапором без адаптера; адаптер це закриває.

Лишилось у `packages/eval/KNOWN-FAILURES.md`: §1, 2, 4–10 — флапи раунду 3 (tense, triple-discipline, reply-max-length, denies-unapplied-card, allergen-proactive прикритий вето); §11–12 — модель через раз ігнорує «Я не їм»/«Мені не можна» у [ПРО ЛЮДИНУ], після 4б ⚠ у коморі це знімає, вето й перегенерація тримають межу; §13 закрито механікою кроку 7.
