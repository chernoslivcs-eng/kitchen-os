# Порожній стан-блок — відповідь, а не тиша

> **Для агентних виконавців:** ОБОВʼЯЗКОВИЙ СУБ-СКІЛ: `superpowers:subagent-driven-development` (рекомендовано) або `superpowers:executing-plans`. Кроки з чекбоксами (`- [ ]`) — для трекінгу.

**Мета:** зробити так, щоб модель ніколи не мусила вигадувати стан кухні через те, що блока про цей стан фізично немає в промпті.

**Архітектура:** блоки стану в `buildKitchenContext` зникають безслідно, коли порожні — крім `[КОМОРА]`, яка присутня завжди і несе сильну шапку-протокол. Ми прибираємо цю асиметрію: кожен стан-блок присутній завжди і при порожньому значенні прямо каже «порожній». Плюс узагальнюємо канон «єдине джерело правди» в `card-rules.md` з однієї лише комори на всі стан-блоки — це друга половина того, що просив M13-ROLE-VOICE п.2 і чого фікс атрибуції (комміт 59de3f8) не покрив.

**Стек:** TypeScript, vitest, pnpm-монорепо. Промпти — версіоновані md-файли в `packages/prompts`.

## Глобальні обмеження

- **Жодних прогонів на живій моделі.** `pnpm eval` і будь-який виклик провайдера — територія власника. Юніт-тести герметичні (`services/api/vitest.setup.ts` видаляє ключі), їх ганяти можна вільно.
- **Правило стоїть біля даних.** Мітка живе в тому блоці, куди модель дивиться. Не зводити в окремий мета-блок — цей урок система вже вивчила тричі (QA5-01, QA7-06, flap calendar-lent).
- **`role.md` НЕ чіпаємо в цьому плані.** Його заборона стосується службової лексики («блок», «контекст»), а не факту порожнечі. Робота крихка — міняємо один шар за раз.
- **Тон порожнього рядка — фактичний, не інструктивний.** «порожній — нічого не записано», а не «скажи людині, що…». Блок описує стан; як про це говорити, вирішує `role.md`.
- Мова коду й коментарів — українська, як у решті репозиторію.
- TDD обовʼязковий: тест → червоний → мінімальний код → зелений → коміт.

## Що НЕ входить (свідомо)

- `serializeRetail(undefined)` лишається німим. `undefined` означає «інтеграції на сервері взагалі немає» — модель не повинна знати про функцію, якої не існує. Це не той самий випадок, що порожній список.
- `serializeOccasions` лишається німим. Його відсутність уже прямо описана правилом у `card-rules.md:17` («Блоку немає або він порожній — традицію ще не розпізнано»).
- Мовчазне обрізання блоків (нотатки капляться на 20, рецепти на 5 — без чесного хвоста «…і ще N», який є в комори). Той самий клас чесності, але окрема робота — див. «Далі» в кінці.

```ts
// QA6-04: без списку в контексті модель у новій сесії казала «порожній» при
// двох позиціях і додавала дубль за один тап.
// M13-ROLE-VOICE п.1: порожній список — це ВІДПОВІДЬ, а не відсутність даних.
// Поки блок зникав, модель не мала куди подивитись і добудовувала стан із
// розмови: живий репро 01.09 — «у тебе зараз два: Pink Tonic і Bitter Lemon»
// при списку без жодного тоніка.
export function serializeShopping(items: ShoppingItemRow[]): string {
  if (!items.length) {
    return '\n\n[СПИСОК ПОКУПОК] порожній — жодної позиції не записано.';
  }
  const lines = items.map((i) => {
    const parts = [i.label];
    if (i.value != null && i.unit) parts.push(`${i.value}${i.unit}`);
    if (i.checked) parts.push('куплено');
    return parts.join(' · ');
  });
  return '\n\n[СПИСОК ПОКУПОК]\n' + lines.join('\n');
}
```

**Чому окремо від решти.** Два ризики, яких немає в інших блоках:
1. **Безпека.** Порожній профіль НЕ означає «алергій немає» — означає «ще не питали». Якщо блок скаже «обмежень немає», модель почне впевнено пропонувати що завгодно людині, якої просто не встигли спитати. Формулювання мусить нести цю різницю.
2. **Онбординг.** `chat.ts:264` вмикає `stage: 2` саме за порожнім профілем, а `onboarding-stage2.md` наказує спитати про обмеження. Блок не має читатись як «уже питали, відповіді немає».

```ts
// Профіль. QA4-02: до цього алергії зберігались, показувались у UI — і не
// впливали ні на що; модель двічі пропонувала мигдаль людині з алергією.
// M13-ROLE-VOICE п.1: порожній профіль — НЕ дозвіл. Людину могли ще не
// спитати (саме на порожньому профілі вмикається онбординг stage 2), і
// тиша не сміє читатись як підтверджене «обмежень немає».
export function serializeProfile(p?: Profile | null): string {
  const parts: string[] = [];
  if (p) {
    if (p.allergies.length) {
      parts.push('АЛЕРГІЇ (тверда межа — ніколи не пропонуй сам): ' + p.allergies.join(', '));
    }
    if (p.antipatterns.length) parts.push('НЕ ЇСТЬ / НЕ ЛЮБИТЬ: ' + p.antipatterns.join(', '));
    if (p.wishes.length) parts.push('ЛЮБИТЬ / ТЯГНЕ ДО: ' + p.wishes.join(', '));
    const eq = Object.entries(p.equipment ?? {});
    const has = eq.filter(([, v]) => v === 'has').map(([k]) => k);
    const lacks = eq.filter(([, v]) => v === 'lacks').map(([k]) => k);
    if (has.length) parts.push('Є ТЕХНІКА: ' + has.join(', '));
    if (lacks.length) parts.push('НЕМАЄ ТЕХНІКИ: ' + lacks.join(', '));
  }
  if (!parts.length) {
    return '\n\n[ПРОФІЛЬ] порожній — обмежень, алергій і побажань ще не записано.'
      + ' Це НЕ означає, що їх немає: найімовірніше, ще не питали.';
  }
  return '\n\n[ПРОФІЛЬ]\n' + parts.join('\n');
}
```

## Ризики

| Ризик | Чому може статись | Що робити |
|---|---|---|
| Наявні тести падають після Задачі 1-3 | якийсь тест стверджував `toBe('')` для порожнього блока | прочитати, що саме тест захищав; якщо це було очікування «блока немає» — воно застаріле, оновити разом із коментарем-чому |
