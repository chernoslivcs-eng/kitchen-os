**Знахідки на стенді, не в постановці**:
1. **Гонитва рефа канвасу**: PNG активного кадру готувався в ОКРЕМОМУ

**Знахідка не з постановки, знайдена на живому стенді, не в тестах**:
React додає `onWheel` як passive listener — `e.preventDefault()` усередині
нього мовчки ігнорується (сторінка й далі скролиться під час зуму колесом
трекпадом), з попередженням у консолі «Unable to preventDefault inside
passive event listener invocation». Правка: нативний
`el.addEventListener('wheel', fn, {passive:false})` на самому
canvas-елементі, а не React-проп `onWheel`. Перша спроба (ручний
`removeEventListener` за попереднім значенням рефа з `canvasRefs.current`,
потім `addEventListener`) не спрацювала стабільно — `.frameCanvas`
переприв'язує реф на кожен рендер (інлайн-колбек, нова ідентичність), і за
живої перевірки `defaultPrevented` лишався `false` навіть після мого явного
виклику. Робоче рішення — React 19 **cleanup-функція з ref-колбека**
(`ref={(el) => { ...; return () => el.removeEventListener(...); }}`)
замість ручного стеження за попереднім елементом. Перевірено прямим
`dispatchEvent(new WheelEvent(...))` у свіжій вкладці (не HMR-стан):
`defaultPrevented: true`.

### Правка 12 (той самий #190, стенд-перевірка на e23640b) — службове слово в кінці групи/клітинки

Було: «Паста з печеними помідорами й часником» → «ПАСТА З | ПЕЧЕНИМИ»
(права група закінчується словом «з», хвіст стартує з «печеними») і
клітинка «ПОМІДОРАМИ Й» (закінчується «й») + окремо «ЧАСНИКОМ». Правило:
жодна група назви й жодна клітинка сітки не закінчується службовим словом
(з, із, зі, й, і, та, в, у, на, до, під, за, по, при, без, для, а) — воно
переходить на початок наступної групи/клітинки; балансування — вже після
цього.

Реалізація (frame.ts):
- `STOPWORDS`/`isStopword` — множина + порівняння без регістру.
- `bestSplit`: кандидат межі `k`, де ЛІВА група закінчувалась би службовим
  словом, пропускається з основного пошуку (право-природно «забирає»
  проблемне слово наступним кроком нижче) — з fallback на
  збалансованість-як-було, якщо взагалі всі варіанти службові (немислимий
  випадок для реального тексту).
- `splitLayoutTitle`: після успішної перевірки ширини — якщо ПРАВА група
  закінчується службовим словом, знімаємо його з кінця (можливо кілька
  поспіль) у ХВІСТ. Це завжди безпечно для ширини рядка: хвіст не має
  обмеження ширини (на відміну від спроби «дорости» ліву групу — тому
  ліво-обробку роблю на етапі ВИБОРУ межі, а не постфактум).
- `chunk` (спільна для хвоста й назв інгредієнтів): жадібний шматок ≤2
  слова, але якщо 2-слівний шматок закінчився б службовим — шматок
  коротшає до 1 слова, службове йде на початок наступного.

**П.13 — інгредієнти повернуто у «Вертикаль».** Було прибрано в самій
постановці спеки (22px — нечитабельно дрібно), замість збільшення —
видалили зовсім. Правка: один рядок (до 2) під назвою, над датою — назви
БЕЗ кількостей через « · », 28px/500, ширина PAD→RIGHT-PAD (96→888, той
самий відступ, що інші кадри), порядок з рецепта, що не влізло — «+N»
останнім елементом.

Реалізація (`frame.ts`): нова `fitVerticalIngredients(ingredients,
measure, maxWidth, size=28, weight=500)` + приватний `wrapTokens` (жадібне
пакування токенів через роздільник, аналог `wrapLines`, але для готових
токенів, не слів одного рядка). Якщо повний список > 2 рядків — шукаємо
найбільший префікс `k`, для якого `[...names.slice(0,k), '+N']` влазить у
2 рядки (перебір `k` від `names.length-1` вниз).

Позиціювання (`render.ts`, `drawVertical`): рядки малюються ПІСЛЯ
`ctx.restore()` ротованої назви, ПЕРЕД існуючим фіксованим `y` дати/часу/
лого (не займає, не зсуває той блок). Ротована назва: pivot
`(PAD+size*0.5, 1520)`, читання знизу вгору — тому її НИЖНІЙ край рівно
`y=1520` (там, де `local x=0`, крапка sage), а сама назва росте ВГОРУ від
цієї точки (менші `y`). Інгредієнти стартують з `y=1520+24`, крок рядка
38px — завжди НИЖЧЕ (більший `y`) за назву, перетину бути не може
геометрично, не лише на конкретних прикладах. Живо перевірено (dev-
harness, canvas напряму, без бекенду): короткий список (3), довгий (8, у
2 рядки без «+N» — реальні назви коротші за синтетичний тест-кейс) і
порожній (0 — рядок просто не малюється) — жодного накладання на всіх
трьох.

Тести (`frame.test.ts`, +4): порожньо → `[]`; один рядок; рівно 2 рядки
без «+N» (hand-verified на fakeMeasure — 8 слів по 4 символи, maxWidth 200,
по 2 слова на рядок); переповнення → «+N» (та сама вихідна, перебір `k`
вручну дав k=3 → `['аааа · бббб', 'вввв · +5']`, тест підтвердив з першого
разу).

**П.14 — тап по прев'ю перемикає кадр (замість свайпу каруселі).**

- Мобільний (390): прев'ю — один кадр по центру, БЕЗ горизонтального
  скролу/каруселі взагалі (той самий патерн `position:absolute` +
  `[data-active]{display:block}`, що вже був на 1440 — тепер спільний).
  Тап/клік по прев'ю — наступний кадр по колу.
- Крапки-індикатори (`.dots`) прибрано. Замість них — у рядку під прев'ю
  підпис кадру + лічильник «2 / 4» (тьмяним, поряд з підписом).
- Подвійний тап/клік більше не скидає кроп (конфлікт з одинарним тапом
  перемикання) — окрема текстова кнопка «Скинути кадр» поряд із
  «Замінити фото», видима лише коли кроп відхилився від
  `{scale:1,x:0.5,y:0.5}` (нова чиста `isCropDefault` у `frame.ts`).
  Додано так само на десктопі (1440, поряд з `.replacePhotoDesktop`) —
  не було в буквальному тексті постановки, але без цього десктоп втрачав
  ЄДИНИЙ спосіб скинути кроп (подвійний клік теж прибрано звідти,
  жест — той самий canvas), тому симетрично.
- Перетягування/пінч/колесо — без змін.
- Тап: зсув <8px І час <300мс від pointerdown до pointerup — рахується
  НЕЗАЛЕЖНО від того, чи можливий кроп на кадрі (заглушка й «Чисте тло»
  теж перемикаються тапом — раніше на заглушці тап відкривав вибір файлу;
  тепер це робить лише кнопка «Додати фото», сам кадр уніфіковано під
  тап-перемикання). Десктоп: клік по великому прев'ю — та сама поведінка
  (той самий canvas/обробники, CSS лише змінює розмір/позицію); мініатюри
  праворуч — окремі кнопки з прямим `onClick`, не зачеплені.

Реалізація (`Share.tsx`): `tapRef` записує `{x,y,t}` на pointerdown ЛИШЕ
коли це перший активний палець (`pointersRef.current.size===0` у момент
перевірки) — другий палець (пінч) одразу обнуляє `tapRef`, тож короткий
пінч не порахується тапом. На pointerup — якщо `tapRef` не null, рахуємо
зсув/час від записаної точки до події відпускання; в межах порогів —
`advanceFrame()` (`setActiveIdx(i => (i+1) % frames.length)`). Прибрано:
`carouselRef`/`slotRefs`/`onCarouselScroll`/scrollIntoView-ефект (нема
скролу — нема чого центрувати), `lastTapRef`/подвійний тап у
`onCropPointerDown`, `onCropDoubleClick`, `onCanvasClick` (заглушка).

CSS: мобільний `.carousel`/`.frameSlot` переведено на той самий
`position:absolute`+`[data-active]` патерн, що вже був на ≥768 (замість
`overflow-x:auto`+`scroll-snap`); `.dots`/`.dot`/`.dotOn` видалено; нові
`.frameCounter`, `.frameRowRight` (групує «Скинути кадр»+«Замінити фото»
праворуч — `margin-left:auto` на самій лише replacePhoto не годиться, коли
resetCrop нема), `.resetCrop`/`.resetCropDesktop`/`.thumbColActions`.

Тести: `frame.test.ts` +4 (`isCropDefault` — дефолт/масштаб/x/y).
`Share.test.tsx` +5: тап перемикає по колу (звірка з порядком мініатюр,
той самий `frames`); зсув ≥8px — НЕ тап (кадр не змінився); утримання
≥300мс без зсуву — теж НЕ тап (`vi.useFakeTimers`); «Скинути кадр» —
з'являється лише коли кроп ≠ дефолт (сесія з реальним `run.id`,
sessionStorage засіяний нестандартним кропом ДО монтування — той самий
шлях, що `loadCrop`/ефект на зміну `runId`), клік скидає рівно до
`{scale:1,x:0.5,y:0.5}`; нема кнопки, коли кроп на дефолті. Два існуючі
тести оновлено під зникнення `.dots`: `selectClean()` тепер клікає
