**Знахідки на стенді, не в постановці**:
1. **Гонитва рефа канвасу**: PNG активного кадру готувався в ОКРЕМОМУ

**Знахідка не з постановки, знайдена на живому стенді, не в тестах**:
React додає `onWheel` як passive listener — `e.preventDefault()` усередині
нього мовчки ігнорується (сторінка й далі скролиться під час зуму колесом
трекпадом), з попередженням у консолі «Unable to preventDefault inside
passive event listener invocation». Правка: нативний
`el.addEventListener('wheel', fn, {passive:false})` на самому
canvas-елементі, а не React-проп `onWheel`. Перша спроба (ручний
`removeEventListener` за попереднім значенням рефа з `canvasRefs.current`,
потім `addEventListener`) не спрацювала стабільно — `.frameCanvas`
переприв'язує реф на кожен рендер (інлайн-колбек, нова ідентичність), і за
живої перевірки `defaultPrevented` лишався `false` навіть після мого явного
виклику. Робоче рішення — React 19 **cleanup-функція з ref-колбека**
(`ref={(el) => { ...; return () => el.removeEventListener(...); }}`)
замість ручного стеження за попереднім елементом. Перевірено прямим
`dispatchEvent(new WheelEvent(...))` у свіжій вкладці (не HMR-стан):
`defaultPrevented: true`.

ВСЕРЕДИНІ `share()`/`download()`/`sendTelegram()` у момент кліку — і досі
без await до жесту (те саме обмеження PR #181: iOS Chrome губить user
activation на await перед `navigator.share()`/`a.click()`). `blobRef`/
`fileRef`/`pngReady` прибрала повністю — `ready` (раніше допоміжний) тепер

кожен `crop`** — лише один раз, на початковому малюванні; «Готуємо
кадр…» видно тільки при першому завантаженні, не на кожен рух кропу.
