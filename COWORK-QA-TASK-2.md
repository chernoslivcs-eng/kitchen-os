# QA-прогін №2: розблоковані області + регресії після 10 фіксів

Перший прогін (`qa-report.md`) заблокувався на FIX-01 — мертвий OpenRouter-слаг моделі не давав генерувати рецепти. Це знято. Ще 9 фіксів на додачу.

Тепер треба:
1. **Перевірити області 5-8** — Recipe / Cook / Share / Journal з реальними даними. Ніхто їх у цій сесії руками не клацав.
2. **Швидка регресія на 10 фіксах** — переконатись, що я їх не поламав більше, ніж полагодив.
3. **Опційно область 9** — Household ролі/invite, якщо стане часу.

## Стан коміту

Гілка `main`, свіжий head — після коміту «QA-report фікси: 8 знахідок Cowork за один прохід». `catalog/expand` не мергнута (юзер відклав каталог).

## Setup

Той самий, що в першому прогоні:

```bash
# Перевірити .env — MODEL_FAST/MODEL_SMART мають бути:
#   MODEL_FAST=anthropic/claude-haiku-4.5
#   MODEL_SMART=anthropic/claude-sonnet-4.5
# Якщо у .env ще старі слаги — оновити. Дефолти в model.ts теж уже оновлено.

curl http://localhost:3000/health | jq
# Має повернути: {"ok":true,...,"model_provider":"openrouter","db":"ok"}
```

Magic-link у stdout API-процесу (той же трюк, що першого разу).

## Область A: Recipe generation (розблоковано FIX-01)

Головна перевірка, що FIX-01 працює. Без цього далі не має сенсу.

- [ ] На Стрічці: «дай рецепт з моцарели» → отримав **proposal**-картку (не intake_diff з двома шоколадами)
- [ ] У картці кожна страва (3 позиції) має кнопку «Рецепт →», не тільки перша (FIX-06)
- [ ] Тап «Рецепт →» на **другу** страву → відкривається саме друга (не перша)
- [ ] Recipe екран рендерить title, ingredients (з UA-одиницями «250 г», «100 мл» — FIX-10), steps
- [ ] Одиниці в інгредієнтах — не «250G»/«250g»
- [ ] Якщо в profile є алергія («молюски») → інгредієнт із мідіями має червону мітку «⚠ молюски»

Якщо будь-що з A ламається — далі можна не йти, спершу репортити.

- Не комітити `qa-report-2.md` — тільки локально
- Не запускай `pnpm smoke` — вб'є existing API
- Не робити destructive проти prod Neon
- Не витрачай токенів надміру — один рецепт коштує ~$0.01, тестуй раз
- Тестові акаунти: `qa2-*@example.com` варіанти

## Deliverable

`qa-report-2.md` у корені із:
1. **Підсумок:** X/Y перевірок пройшли, Z провалів (структурно за severity)
2. **По одному блоку на провал** (формат вище)
3. **Оцінка**: чи все ще є blocker'и, чи готово до Vercel-deploy'ю
4. **Опційно**: 3-5 речень про UX-відчуття після фіксів — стало краще/гірше/те саме
